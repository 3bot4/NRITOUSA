# Runbook — publishing a monthly visa bulletin page

**Time: about 15 minutes**, most of it waiting for a build. Everything below is
data plus one line of code; there is no page to write.

URL shape: `/visa-bulletin/<month>-<year>` (e.g. `/visa-bulletin/september-2026`).
The page itself is generated by `src/components/visa-bulletin/MonthPage.tsx`
from the snapshot data — you never edit a month page by hand.

---

## The rule that comes before every step

**Publish a month page only after the Department of State has released that
bulletin.** Not when a prediction is confident, not when a newsletter leaks a
figure, not on the day it is "due". A month page asserts exact cutoffs as fact;
if the bulletin is not out, we do not have facts.

Forecasts belong on the predictions pages (e.g.
`/visa-bulletin/october-2026-predictions`), which are framed as forecasts.

`src/lib/visaBulletinMonths.test.ts` enforces the mechanical half of this: every
entry in `PUBLISHED_MONTHS` must have a real snapshot behind it, and the
previous month's snapshot too, or the suite fails.

---

## Step 1 — confirm the bulletin is out

Open the Department of State visa bulletin page and check the newest month
listed:

https://travel.state.gov/content/travel/en/legal/visa-law0/visa-bulletin.html

> `travel.state.gov` blocks automated fetches (403). Do not try to script this —
> use a browser, or `WebSearch` with `allowed_domains: ["travel.state.gov"]`.

Releases usually land in the second week of the preceding month and have
recently slipped into the third.

## Step 2 — ingest the data

```bash
node scripts/build-visa-bulletin-data.mjs
```

This regenerates, from the bulletin source data:

- `data/visa-bulletin/snapshots/<YYYY-MM>.json` — the fully populated month
- `data/visa-bulletin/current.json` — the live bulletin the whole site reads
- `data/visa-bulletin/history.json` — the change-point series the charts use
- `data/visa-bulletin/index.json`, `ingest-log.json`

Then check `current.json` by eye:

- `bulletinMonth` is the new month
- `source` / `sourceLabel` point at **that month's** bulletin URL
- `adjustmentOfStatusChart`, `...ChartStatus` and `...ChartMonth` reflect the
  **USCIS** filing-chart determination, which is published separately from the
  bulletin and can lag it. If USCIS has not posted for the new month, set
  `adjustmentOfStatusChartStatus: "pending"` and leave `...ChartMonth` on the
  month the determination actually covers. The UI then says the determination is
  pending instead of asserting a chart — do not "tidy" this by guessing.

USCIS chart determination: https://www.uscis.gov/visabulletininfo

## Step 3 — wire the snapshot into the month pages

`src/lib/visaBulletinMonths.ts`:

1. Add a static import for the new snapshot and an entry in `SNAPSHOTS`.
   Imports are static so the pages stay statically generated.
2. Add the month to **`PUBLISHED_MONTHS`**. This single line creates the page,
   the sitemap entry, the search-index entry and the hub listing.

```ts
import s202610 from "../../data/visa-bulletin/snapshots/2026-10.json";
// ...
const SNAPSHOTS = { /* ... */ "2026-10": s202610 as BulletinSnapshot };
export const PUBLISHED_MONTHS: string[] = ["2026-10", "2026-09"];
```

Keep the previous month's snapshot imported too — the page computes
month-over-month movement against it, and the test will fail if it is missing.

## Step 4 — the pages that reference the current bulletin

These are separate from the month page and are easy to forget:

- `currentBulletinNote` in `src/lib/visa-bulletin.ts` — the manually maintained
  movement note surfaced on `/visa-bulletin`, `/tools/priority-date-checker`,
  `/green-card` and the immigration tracker. Update it or clear it.
- The movement labels on the immigration tracker. Per
  `docs/DATA-UPDATE-PLAYBOOK.md` §1 these are the easiest silent bug in the
  cluster — a label saying "advanced" next to a retrogressed date.
- `/visa-bulletin/eb1-india`, `/eb2-india`, `/eb3-india` — category-page prose
  is **not** evergreen. If a category went Unavailable or a cutoff returned, the
  framing needs to change, not just the number.
- Retire or reframe any predictions page the bulletin has now answered.

## Step 5 — gates

```bash
npx tsc --noEmit
npx vitest run          # visaBulletinMonths, visaBulletinDates, freshness, sitemap
```

The visa-bulletin suites are the ones that catch a bad ingest: date scenarios,
freshness, legal-wording and the sitemap/search-index cross-check.

## Step 6 — internal links

The month page links out to the category pages automatically. Add the link
*in* from anywhere the new month is discussed — usually
`/visa-bulletin/monthly-update` picks it up on its own via `MonthIndex`.

## Step 7 — ship and ping

```bash
git add -A && git commit -m "October 2026 visa bulletin" && git push
```

Pushing to `main` deploys to production. Once it is live:

```bash
npm run indexnow
```

Ping the **production** URL, never a preview URL.

---

## Why the month pages exist at all

"visa bulletin [month] [year]" was 18,100 searches a month for April 2026 alone,
and the pattern repeats every single month. A hub page that gets edited in place
each month captures none of that, because the query is month-specific. One page
per bulletin, published the day it drops, is the whole play — which is why this
runbook optimises for speed over polish.
